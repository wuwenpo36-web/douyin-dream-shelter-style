# 中文阅读指南

[返回首页](../README.md) · [完整原文](../SKILL.md) · [填写单集简报](episode-brief.md)

这份导读按制作顺序解释原始 skill 的重点，便于先理解，再进入对应专题。它是中文整理，不是完整逐字翻译；具体输出规范和细节以链接中的原文件为准。

## 1. 先确定本次交付什么

| 交付物 | 输出重点 |
| --- | --- |
| 创意列表 | 给出有差异的灾难、变身物件和庇护所形式，讲清视觉钩子与搭配原因 |
| 分镜或客户大纲 | 写清场景、动作、体验和转场，使用可以直接执行的制作语言 |
| GPT Image 提示词 | 默认一段可复制的英文 Prompt，把禁止事项整合在同一段内 |
| 改图提示词 | 先指定唯一要改的区域，再锁住镜头、构图、场景和其他物件 |
| 视频提示词或交接简报 | 交代时间顺序、物理因果、POV、遮挡、揭示、落地与连续性 |
| 室内方案 | 规划连贯路线，并让各空间的用途、构图和情绪有所区别 |
| 品牌方案 | 让产品或服务改变角色体验，并保持原有庇护所叙事 |

用户说“直接给我 prompt”时，只给提示词。用户声明参考图只是错误示例、不会上传时，最终提示词必须独立描述画面。

详见：[主规则](../SKILL.md) 和 [图片提示词规范](../references/gpt-image-prompt-contract.md)。

## 2. 用职业、任务和近场威胁建立开场

角色需要有正在进行的工作：快递员驾驶载货三轮车、维修工操作工具、船员控制缆绳。服装、装备、车辆、货物与路线共同证明身份，也解释角色为什么处于危险中。

先区分两种开场：

- **明确要求灾前首帧：** 保留相对平静，只放入两三个预兆，如异常天空、拉紧的缆绳、裂缝、飞溅、落石或回流水。
- **视频留人开场：** 从“最后安全一秒”开始。身体已经依附于即将失效的路线或支撑，主威胁在近处，约 0.5–1.5 秒内可能发生接触。

让一个大型、快速、接近镜头的事件成为焦点，同时保持方向可读。职业和物件来源尽量在同一画面交代。

8–12 秒开场可以参考“即将接触 → 实际冲击和遮挡 → 短暂恢复方向 → 操作物件 → 第二次材质遮挡 → 庇护所揭示并继续入内”的节奏。原文时间只是参考形状，需要按动作复杂度调整。

声音也跟随两个高潮：灾难接触声对准真实撞击；恢复方向时降低强度；物件动作有明确物理声；变身和揭示再形成第二次抬升。

详见：[POV、灾难与变身](../references/pov-disaster-transformation.md)。

## 3. 灾难必须解释故障

基本因果链是：**环境原因 → 可见预兆 → 结构或物理失效 → 安全路线中断 → 身体反应。**

| 灾难设定 | 可用于叙事的直接后果 |
| --- | --- |
| 极端高温 | 路面软化、金属膨胀、玻璃热裂、电气过热、受热岩体落石 |
| 台风 | 横向飞散物、构件掀起、支撑断裂、屋顶撕裂、风暴潮 |
| 山地暴雨 | 土体饱和、滑坡、泥石流、树倒、路边塌陷、能见度下降 |
| 风暴潮 | 水体逼近、倒灌、漂浮残骸、失去抓地力、街道或隧道进水 |
| 冰雪 | 摩擦降低、积雪超载、白化视野、雪板滑脱、表面脆化 |

上述是虚构内容的视觉因果设计方向。每个镜头仍需明确“什么作用于什么”，避免只写灾难名称再接一个无关爆炸。

## 4. 第一人称由身体运动建立

镜头默认位于真实人的眼睛高度，并与身体的姿势和受力一致。

- 行走、奔跑、攀爬、滑行、跌落、骑行有不同的高度、震动和视差。
- 手脚只在真实动作需要时进入画面；不要长期悬着双手，或用持续出现的膝盖和直腿证明第一人称。
- 水滴必须由水雾或浸水产生，并停留合理时长；风通过植被、雨线、衣物和飞散物表现。
- 跌落需要加速与尺度变化；落地装置需要压缩、下沉、回弹或其他消能过程。
- 站在移动平台上时，人、承载物和眼睛镜头一起移动，固定环境提供反向视差。
- 遮挡前后保持方向、速度、衣物、物件所在手、镜头水迹、天气和声音连续。

详见：[第一视角与运动规则](../references/pov-disaster-transformation.md)。

## 5. 变身物件有来源、有动作、有专属材质

使用完整的动作链：

1. 物件已在画面中，或明确从口袋、包、车内、工作台取出。
2. 手以合理姿势抓住物件。
3. 完成一次清楚的抛出、打开、按压、打破或放置。
4. 发生可以看见的接触或触发。
5. 物件对应的材质反应扩散，并遮满或基本遮满画面。
6. 遮挡散开后，巨型庇护所才出现。
7. 身体保持原有动势，继续接近可进入的位置。

| 物件 | 可继承的材质语言 |
| --- | --- |
| 松果 | 木质颗粒、棕色粉尘、树脂色雾气 |
| 漂流瓶 | 淡蓝冷凝、海雾、玻璃质感 |
| 巧克力 | 可可雾、黏稠带状流动、棕色缎面感 |
| 芒果 | 金色蒸气、果肉纤维弧线 |
| 快递箱 | 纸纤维、封箱胶带、几何面板 |
| 冰晶 | 霜雾、折射碎片、冷气 |

物件不能凭空出现、复制或无故消失；成品建筑不能在触发前露出。

## 6. 巨型外观同时解决尺度与进入方式

用正常尺度的门、栏杆、台阶、灯具和多层窗格证明建筑体量。把主题转成屋顶、结构、材质、交通路径和少量辨识细节。

需要“极近、极巨大”时，把近距离、画面占比、跨越多个边缘的裁切、天空与前景限额一起写清。案例中 85–95% 的画面占比帮助解决过远过小的问题，但不能由此推断建筑还原或品牌文字也已成功。

安全感来自厚实外壳、受保护入口、深檐、密封开口、排水和清晰结构。进入方式必须匹配环境：与船接触的梯子、对准车辆的坡道、吸收落地动量的软垫、端点明确的滑道等。

详见：[揭示、落地与进入](../references/pov-disaster-transformation.md) 和 [案例库](../references/case-library-and-failure-modes.md)。

## 7. 三空间是一段连续的恢复过程

| 顺序 | 空间目的 | 可选内容 |
| --- | --- | --- |
| 到达与缓冲 | 先解决外部灾难带来的实际问题 | 清洗、烘干、更衣、装备存放、充电、热水 |
| 标志体验 | 提供这一集最有记忆点的空间 | 雨庭、生态谷、壁炉书房、温室、观景或音乐空间 |
| 私密恢复 | 给角色稳定、放松与被照顾的感觉 | 卧室、浴室、安静客厅、影音室、睡眠舱 |

通过真实走廊、桥、花园、楼梯或材料过渡连接，各空间需要不同构图、焦点、顶面、色彩比例和情绪用途。

保留可步行的通路。控制沙发和前景家具大小；使用受到保护的适中窗户、深窗洞、扶手、防滑地面和必要物资。

主题应进入建筑语言，例如松果的叠层屋顶、漂流瓶的软木吸音、披萨的放射结构和香草供应温室、巧克力的缎面曲线与流动路线。

详见：[室内与图像编辑](../references/interiors-and-image-edits.md)。

## 8. 氛围由光源、材质和活动组成

写清外界天气与色温、主要灯具、次要光源、接收光的材质，以及角色在空间里的安静活动。

原文建议用约 2700–3000K 的暖色住宅光作为主要来源，并以吊灯、壁灯、台灯、落地灯、壁炉或任务照明解释亮度。夜景也要保留家具和动线的可读性，RGB 与霓虹只承担受控点缀。

配色可采用“一主色＋两辅色”或“两主色＋一点缀”。冷色外界反光主要停留在窗边、附近地面或家具边缘，室内材料本体保持温暖。

## 9. 图片提示词先分配参考图角色

先确定是纯文生图、参考引导的新图，还是保持原图的局部修改。

- 每张参考图承担清楚的职责：底图、产品结构、尺度、角色、情绪，或错误示例。
- 默认输出单段英文 Prompt，在段内注明比例、镜头、场景、主体关系、尺度、人体、天气、材质、实际光源、精确文字和限制。
- 包装图只提供包装时，不把白背景和场景一起搬进结果。
- 品牌文字使用批准的字面内容，产品保持真实手持尺度。
- 白底资产使用无缝纯白底、轻微接触阴影；多视图保持同一几何和标记。
- 局部编辑先写修改对象，再锁定透视、反射、阴影、裁切及所有无关内容。删除物件后重建其后方表面。

详见：[GPT Image Prompt Contract](../references/gpt-image-prompt-contract.md)。

## 10. 品牌通过体验发生作用

品牌场景遵循：**可信痛点 → 合理环境 → 自然使用 → 可见响应 → 故事继续。**

把抽象诉求转成具体改变：湿变干、冷变暖、饥饿得到食物、低电量获得充电、疲惫获得支撑与睡眠。来源品质可以变成生态谷，服务可以变成受保护的雨庭和一组真实动作。

保持多空间和连续旅程。账号不需要其他人时，用机器人、吉祥物、移动篮子和自动设施完成递送、引导和照料。

软性睡眠产品需区分浅层手压、身体支撑、翻身后的压力迁移；单纯的深凹陷不能同时说明这些体验。产品文字、包装、比例及已批准宣称需要保持准确。原文提醒，生成视频中的文字未必精确，要求完全清晰时需考虑后期处理。

结尾可落在热饮、音乐、宠物、休息或自然留在画面中的产品。参考第三人称恢复结尾时，仍要满足原文对连续镜头路线的限定。

详见：[品牌融入](../references/brand-integration.md)。

## 11. 使用案例时保留证据边界

原始案例包括洪水竹桥与椰子树屋、瀑布悬崖与松果树屋、风浪帆船与漂流瓶飞艇、沿海隧道与防洪庇护所、巴黎冰面与巧克力宫殿、哀牢山快递员与移动庇护所，以及芒果浮岛、披萨飞艇和蝎子飞艇等。

案例库另行记录了几类“局部得到确认”的迭代：

| 迭代 | 可以借鉴 | 仍需另行解决 |
| --- | --- | --- |
| 缩短 15 秒片段终点 | 删去最后目的地或交互，给因果动作留时间 | 车辆左右关系、烟雾连续、POV 是否正确 |
| 极近极大的外观揭示 | 同时控制距离、占比、裁切和背景限额 | 建筑保真与清晰品牌文字 |
| 产品舒适体验链 | 触摸、材料响应、支撑、睡眠与外界变化的方向 | POV 转第三人称、延时变化表现 |
| 平台入门与室内弹跳路线 | 整体路线框架 | 平台承载、手脚可见性、弹跳物理和动作僵硬 |

不要把局部改善当成整集已经验证。详见：[完整案例与修复规则](../references/case-library-and-failure-modes.md)。

## 12. 交付前检查

- [ ] 第一帧的职业、路线和主威胁可以迅速读懂。
- [ ] 灾难直接造成当前故障，身体反应符合受力。
- [ ] POV、高度、手脚和镜头附着关系一致。
- [ ] 物件来源、抓握、触发、遮挡、揭示连续。
- [ ] 庇护所足够大、可居住、有安全感，且没有提前露出。
- [ ] 落地、接驳和进入路线可以成立。
- [ ] 三空间相连，各自有不同的功能和构图。
- [ ] 动线畅通，窗户受保护，设施有作用。
- [ ] 光有实际来源，夜景保持可读，配色受控。
- [ ] 品牌改变角色体验，产品尺度与文字来源明确。
- [ ] 案例只引用得到支持的局部机制。
- [ ] 输出范围和格式符合本次要求。
